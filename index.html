CASE STUDY 01 WEB INTERFACE / INFORMATION ARCHITECTURE

Cloudhire Talent Portal

Organizing technical talent discovery by skills, roles, and career paths.

Interface redesign
UPDATED INTERFACEFind the right path to talent.

Multiple discovery routes, a consistent card system, and recognizable categories.

THE CHALLENGE

From promotional overview to navigable categories

The original Cloudhire presentation emphasized the platform's value to employers. The updated interface brings the actual browsing choices to the foreground.

DESIGN DECISIONS

  • Three entry points: Explore talent by skill, role, or career.
  • Consistent components: Repeated tiles support scanning.
  • Clear section headings: Content is grouped by employer intent.
View original concept and design notes +

Next iterations: Improve small text, make each “see all” label specific to its category, ensure focus states and contrast, and demonstrate what happens when a category is selected. These are recommendations, not tested outcomes.

CASE STUDY 02 RESPONSIVE UI / INSURANCE INFORMATION

Zeneith Insurance Renewal

Reimagining a dense insurance enrollment table as a more readable renewal overview.

Desktop + mobile

THE CHALLENGE

Make dense coverage information easier to scan

The source screen combined carrier, status, renewal dates, contribution details, and plan information in a wide administrative table that becomes difficult to use on narrow screens.

DESIGN DECISIONS

  • Visual hierarchy: Emphasize provider and renewal information.
  • Distinct sections: Use separate visual treatments for insurance providers.
  • Responsive layout: Stack details into a vertical mobile reading flow.
View the original challenge and design tradeoffs +

Important tradeoffs: The high-fidelity concepts emphasize renewal information, but the original administrative actions, approval links, and status indicators need to be accounted for in a complete product workflow. Smaller text and color contrast also merit accessibility testing. No user testing or measured improvements are claimed.

03 / DESIGN APPROACH

Start with the user.
Design for clarity.

01

Understand

Identify what the interface needs to communicate, who will use it, and what information matters most.

02

Organize

Establish content groups, navigation pathways, hierarchy, and reusable patterns.

03

Design

Translate the structure into clear layouts that adapt to desktop and mobile contexts.

04

Evaluate

Review usability risks, accessibility, missing workflow steps, and what should be validated with users.

This is my approach to design; project-specific research, usability testing, and performance results are not implied unless explicitly documented.
